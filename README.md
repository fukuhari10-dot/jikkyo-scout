# 実況スカウト データ収集キット（アプリ名は仮）

YouTube の公開情報を定期的に集めて、アプリが読む `data/latest.json` を作ります。
サーバー代 0 円で動かす前提です（GitHub の公開リポジトリ + GitHub Actions + GitHub Pages）。

## 配信者をもっと集める（専門でなくてもOK → 人が選ぶ）
集めるのは2種類です。
- 🎮 **ゲーム実況**（プロスピの実況・配信をする人）：`bash more_mac.sh`
- ⚾ **プロ野球**（球団ファンのYouTuber。現地観戦・応援・試合の振り返り・ニュース考察・ドラフト・球場グルメ）：`bash more_fan_mac.sh`

1. ターミナルで上のどちらかを動かす（APIキーを聞かれるので貼り付ける）
2. 動画を出しているチャンネルを広く集める（約1,800ユニット・2〜4分）。最近15本のうち、その種類の動画が2本以上の人が候補（片方を集めても、もう片方の候補は消えない）
3. ブラウザに「載せる配信者をえらぶ」画面が開く。上のタブ「🎮 ゲーム／⚾ 野球ファン」で分けて見られる。「専門・多め・ときどき」の目安を見ながらチェック → 「この内容で保存」。種類がちがう人は行の中で切りかえる
4. 保存するとそのままデータを作り直す。アプリの黒い帯から `data/latest.json` を読み込み直す
- アプリに出す動画・ライブ・配信予定は、ゲーム実況の人はプロスピのタイトルのもの、野球ファンの人はプロ野球の話題のタイトルのものだけ（ゲームの動画は野球ファンには出ない）
- `latest.json` のチャンネルには `genre`（`game`＝ゲーム実況、`fan`＝プロ野球）が付く
- 選び直したいときは `bash curate_mac.sh`（集め直さない。APIの量も使わない）
- 選ぶ画面の「全部の動画を出す」をONにした人は、タイトルに関係なく全部の動画・ライブを出す（最初は「専門」の人だけON）

## アプリごと GitHub Pages に置く（自動更新・スマホで開ける）
- `index.html` はアプリ本体。GitHub Pages に置くと、同じ場所の `data/latest.json` を自動で読む（黒い帯から読み込む必要なし）
- 公開されるURL：`https://<ユーザー名>.github.io/<リポジトリ名>/`（iPhone の Safari →共有→「ホーム画面に追加」でアプリのように使える）
- この形では、広場・ポイントはまだ各自のスマホの中だけ（みんなで共有するのはサーバーを動かしてから）

## 全自動で動くもの（人の作業はいらない）
- **試合日程**：毎日3:20に NPB 公式サイトの公開日程（日時・対戦・球場）を読んで `data/games_npb.json` を作る。アプリの「実況」に今日の試合が出る
- **配信者の追加**：毎日3:20に新しい動画から2種類の人をさがして、条件を満たす人を `channels.json` に自動で足す
  - 🎮 ゲーム実況の配信者：最近15本中プロスピ3本以上・プロスピが4割以上・登録者300人以上・公式でない
  - ⚾ 球団ファンのYouTuber：最近15本中、ゲームでないプロ野球の話題（現地観戦・応援歌・反省会・ドラフトなど）が3本以上・4割以上・登録者300人以上。球団・リーグ・テレビ局・スポーツ新聞のチャンネルは入れない。さがす言葉は毎日5つ＋日替わりで1球団（「〇〇ファン」）
  - 両方に当てはまる人はゲーム実況にする
- **配信者を外す**：最近その種類の動画（ゲーム実況＝プロスピ、プロ野球＝野球の話題）を1本も出していない人は毎時の更新で自動で外す（また出しはじめたら自動で戻る）
- **ジャンル・球団・配信する人**：動画タイトルやチャンネル名から自動で付ける（はっきりしない人には付けない）。球団ファンのジャンルは「現地観戦・応援・試合振り返り・ニュース・考察・ドラフト・二軍・球場グルメ」
- 選ぶ画面（curate）でチェックを外した人は `blocked.json` に入り、自動では二度と追加されない

## 試合日程（games.csv）は書かなくてよい
- 自動の日程がまちがっているときや、CS・日本シリーズの対戦が決まったときだけ、上書きしたい試合を書く
- アプリの「みんな」→「球団」に今日の対戦カードを出すための表。1行に1試合：`日付,開始,ホーム,ビジター,球場`（例 `2026-10-01,18:00,ロッテ,日本ハム,ZOZOマリン`）
- 書いて GitHub にアップロードすると、10分以内にアプリに出る（これから7日分）
- 書かなくても、球団ごとの「試合実況スレ」は毎日自動でできる

## まず動きを見たいとき（5分）
1. Google Cloud で YouTube Data API v3 を有効にして APIキーを作る（下の「準備」の1）
2. このフォルダを Mac に置いて、ターミナルで `bash start_mac.sh`（キーを聞かれるので貼り付ける）
3. できた `data/latest.json` を、アプリ上部の黒い帯「タップで本物のデータを読み込む」から選ぶ
   → 本物の配信者・登録者数・動画・ライブで動きます（1回読み込めば次から自動で表示）

## 準備（最初の1回だけ）
1. Google Cloud で新しいプロジェクトを作り、「YouTube Data API v3」を有効にして API キーを発行する
2. GitHub に**公開**リポジトリを作り、このフォルダの中身を入れる
   （公開リポジトリなら Actions が無料で回せる。データはもともと公開情報）
3. リポジトリの Settings → Secrets → Actions に `YT_API_KEY` を登録
4. Settings → Pages で main ブランチを公開 → アプリは
   `https://<ユーザー名>.github.io/<リポジトリ名>/data/latest.json` を読む
5. 載せる配信者を入れる（**Mac で1回だけ**）
   ```
   export YT_API_KEY=発行したキー
   python3 fetch.py --mode seed        # seed_names.json の名前・@ハンドルから本物のチャンネルを探す
   ```
   - `channels.proposed.json` ができる。**載せるのはプロスピ専門だけ**：最近の動画の7割以上がプロスピの人が `check: OK` になる。OK 以外は追加されない
   - 名前で探した結果なので、別人のチャンネルが混ざっていたらその行を消す
   - 残した行に `tags`（リアタイ・ガチャ など）・`team`（球団）・`streamer`（配信する人は true）を書く
   ```
   python3 fetch.py --merge-proposed   # channels.json に足す
   ```
   - あとから足すときは channels.json に `{"handle": "@ハンドル"}` だけ書いてもよい（IDは自動で調べて data/handles.json に保存）
   - 以降は `data/candidates.json`（毎日自動で見つかる候補）と掲載申請から追加

## 更新の間隔
| 内容 | 間隔 | モード |
|---|---|---|
| ライブ中・視聴者数・今夜の配信予定・新着動画 | 10分ごと | live |
| 登録者数・動画の再生数 | 1時間ごと | full |
| 新しい配信者の候補さがし | 1日1回（3:20） | discover |
| 22時台の同時視聴者数（1位予想の答え合わせ） | 22時台の最初の更新 | live → `data/snap/日付.json` |

※ GitHub Actions の定期実行は混雑時に5〜15分遅れることがある
※ 登録者数は YouTube 側で上3桁に丸められる（例：12,345人 → 12,300人）

## API の使用量（1日の上限 10,000）
300チャンネルの場合の目安:
- live：videos.list 約18回 × 144回/日 ≈ 2,600
- full：channels.list 6回 + videos.list 約30回 × 24回/日 ≈ 860
- discover：search.list 12回（ゲーム6・プロ野球6） × 100 = 1,200
- 合計 ≈ 4,700 / 10,000（100チャンネルなら約2,200）

チャンネルごとの新着チェックは RSS（割り当てを消費しない）を使っています。

## テスト
```
python fetch.py --selftest
```

## サーバー側
ポイント・ランキング・応援票・広告の検証・課金は `tuber-scout-backend`（Firebase）を参照。
サーバーは `DATA_BASE`（このリポジトリの GitHub Pages の `/data`）から latest.json と peaks を読みます。

## 掲載中の人のチェック
- 毎時の更新で、掲載中なのに最近その種類の動画（プロスピ／プロ野球の話題）を1本も出していない人を `data/review.json` に出す → 確認して外すか決める
- 毎日の候補さがし（candidates.json）にも `senmon: true/false` が付く

## 注意
- YouTube API の規約に合わせ、登録者数の履歴は残さず、増加数・伸び率などの独自の指標も作らない。予想用の `data/snap/` は30日で自動で消す
- 載せるのは公開されている情報（チャンネル名・登録者数・動画タイトル・サムネイル）だけ。サムネイルは YouTube の画像URLをそのまま表示する（保存・加工しない）
- 本人から「載せないで」と言われたら channels.json から消す（掲載停止の窓口をアプリに用意）
